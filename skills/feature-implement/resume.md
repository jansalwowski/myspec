# Resuming a Run

Read from SKILL.md Step 1 (Resume), at startup only, on the trigger SKILL.md gives. Never apply it mid-run: a `[~]` task there is one this session dispatched, and its worktree is live. `<plugin lib>` is the path SKILL.md resolves.

1. **Scan every task checkbox.**
   - `[x]` = already done — skip entirely
   - `[~]` = was in progress when the previous session stopped — unless its phase finished implementing (step 3), re-execute this task from scratch. When it ran in a worktree, first clear the stale one with `"<plugin lib>/task-worktree.sh" discard <slug>` (a no-op when none exists) — `create` refuses an existing slug, and the partial work never passed review. The slug is `<feature>-t<N>` for a parallel task, and `<feature>-p<N>` for a concurrent phase (parallel-phases.md), which then runs again from scratch, every task of it
   - `[ ]` = todo — execute normally
2. **Recover the run's state.** `BASE_SHA` comes from the `Base (feature)` entry, and for the phase being resumed, `PHASE_BASE` from its `Base (Phase N)` entry, so the phase review still spans the commits made before the restart. A plan from before these entries has none: take `BASE_SHA` from `git merge-base HEAD <integration branch>` and record the phase base afresh. `$STATE` is what `"<plugin lib>/implement-state.sh" init {feature}` prints (Step 2 runs it again and gets the same path); packages, logs and stage stamps from before the restart are there.
3. **A phase that finished implementing resumes where it stopped, never by re-executing its tasks** — its work is already on the feature branch, so re-implementing it would redo the phase on top of its own commits, and the review would span both copies. This needs the phase's `Base (Phase N)` entry from step 2. Read its stage stamps, `$STATE/phase-N.times`:
   - **last stamp `done`** — the review passed: finish 4e (flip the tasks to `[x]`), then 4f.
   - **last stamp `review` or `fix-R`** — resume at the phase review, SKILL.md Step 4 item (b) — not Step 4b, the milestone checkpoint: a fresh review over `PHASE_BASE`, passing the existing `$STATE/phase-N-verify.log`. A fix loop cut off mid-round starts over from that review's findings; the rounds its `Fix base (Phase N, round R)` entries log count toward the five. An interrupted fixer's uncommitted edits are part of the dirty tree Step 0 already had the user resolve: committed, the fresh review covers them; stashed, they are gone.
   - **last stamp `barrier`** — resume at Step 4a. A task worktree still present is merged, not discarded (the barrier starts only once every task is done), and a merge still in progress (`git rev-parse -q --verify MERGE_HEAD` exits 0) is finished first, as parallel-tasks.md resolves a conflict.
   - **a concurrent phase with no `barrier` stamp** — parallel-phases.md logs its `Base (Phase N)` only after the phase finished implementing, just before the merge, so that entry alone means the work is done. Finish the merge: a merge in progress is completed as above; a `<feature>-p<N>` worktree still in `git worktree list` is merged with `"<plugin lib>/task-worktree.sh" merge <feature>-p<N>`, not discarded. Then resume at Step 4a.

   Any other phase — no `Base (Phase N)` entry, or no stamps (a run from before them) — re-executes its `[~]` tasks as step 1 says.
4. **Find where to resume.** Start at the first milestone containing any non-`[x]` task — unless an earlier milestone, or any milestone when every task is `[x]`, carries `**Checkpoint probes:**` without a passing entry per probe; resume at the first such milestone's probe gate (Step 4b) instead. A passing entry is a `Probe` line with PASS (SERVED for a `D<n>` demo) or a `Waiver` line.

Step 0 still asks where to work, and Step 2 still runs: `implement-state.sh init` returns the same `$STATE`, and the orchestration marker is set again for the new session.
