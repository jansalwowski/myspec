# Feature Discover — Document Templates

Reference templates for output files generated by the `feature-discover` skill.
Load this file when generating output in Steps 4, 6, and 8.

## Confirmation Findings Template (Step 4)

```markdown
## Discovery Findings: {Feature Name}

### What it does
[2–3 sentence behavior summary]

### Files involved ({N} files)
- `path/to/Component.vue` — [role]
- `path/to/store.ts` — [role]

### Integration points
- **Internal**: [list of internal modules or features]
- **External**: [list of external APIs/services, or "none found"]

### Feature flags / gates
- `{FLAG_NAME}` — [behavior when enabled/disabled, or "purpose unclear"]

### Translations
- `{translation.key}` — [what it labels]

### Open questions
- [anything unresolved after Q&A]

### Complexity assessment
[Simple / Moderate / Complex — with brief reasoning]
```

## discovery.md Frontmatter

```yaml
title: "{Feature Title} — Discovery"
feature: {feature-name}
status: confirmed
discovered: {TODAY}
source: code-only
```

## spec.md Format

```yaml
title: "{Feature Title}"
status: draft
phase: 1
priority: P{0|1|2}
spec_version: 1
created: {TODAY}
last_updated: {TODAY}
source: discovered
```

Required sections: Overview, Goals, User Stories / Requirements, Acceptance Criteria, Out of Scope, Open Questions.

**Generation rules:**
- Derive everything from observed code behavior — do not invent
- User stories describe what the feature enables, not how it works internally
- Acceptance criteria come from gate conditions, validation rules, and error states found in code
- Open Questions carries over verbatim from `discovery.md`
- No file paths, class names, or code in spec.md

## tech-spec.md Format

```yaml
title: "{Feature Title} — Technical Specification"
status: draft
based_on_spec_version: 1
created: {TODAY}
last_updated: {TODAY}
source: discovered
```

Required sections:

### Architecture
How this fits into the system, key components and their responsibilities.

### Key Interfaces / Types
Actual TypeScript types and interfaces found in code (quote them directly).

### File Inventory
All files discovered during exploration:

| File | Type | Role | Action |
|------|------|------|--------|
| `path/to/file.vue` | Vue component | [role] | exists |

Action is always `exists` for discovered files (not `add`/`create` — this is not a plan).

### API Calls
Actual endpoints found in code:

| Method | Endpoint | Purpose |
|--------|----------|---------|
| POST | `/api/...` | [from Q&A answer] |

### Feature Flags & Gates
| Flag | File | Behavior |
|------|------|----------|
| `FLAG_NAME` | `path/to/file` | [what it controls] |

### Integration Points
External services and their roles (from Q&A answers).

### Decisions
Notable implementation choices observed in code — why something was done a particular way if evident.

### Open Questions
Carry over from discovery.md.

**Generation rules:**
- File Inventory must include ALL files found in exploration
- No checkbox steps — this is existing code, not a plan
- Quote real types and interfaces from the code directly

## dependencies.md Format

```yaml
title: "{Feature} — Dependencies"
purpose: "Cross-feature dependency tracking"
updated: {TODAY}
feature: {feature-name}
source: discovered
```

Sections:
- **Upstream Dependencies**: what this feature depends on (other features, modules)
- **Downstream Dependents**: what depends on this (unknown unless evident from code)
- **External Dependencies**: npm packages and external services found during exploration
